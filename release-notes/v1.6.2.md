# WhatBattery 1.6.2

Older iPhones and iPads can now be read, and the Health tab draws a chart in days instead of months, exports per device, and produces a one-page report. macOS 14 and later, Apple Silicon.

## Older devices keep their battery data somewhere else

Devices from before the iPhone 8 and iPhone X generation (late 2017) publish their battery under a different name than everything since. WhatBattery only asked at the newer address, so an older device answered honestly that it had nothing there, and the tab reported it as connected but with no battery. This is why an iPad Pro 10.5" sat unreadable next to an iPhone X that read fine.

WhatBattery now checks the older location whenever the newer one comes up empty. Newer devices are unaffected: they answer the first question, same as before.

One honest caveat: this was built without a pre-2017 device on the bench, so it is correct against the documented shape of the older data rather than proven against hardware. If your older device still will not read, say so and include what the tab reports.

## The health chart no longer takes two months to appear

The Health tab plotted one point per calendar month, so a fresh install waited two months to draw anything, purely because months were the resolution. The daily records were already being kept; the chart just was not using them.

There is now a Daily/Monthly picker. Daily plots every recorded day, which means a chart after two days, and lists the last month of readings. Monthly stays as it was for the long view.

## Export a device's health history, or print it

Each device card in the Health tab gets an Export menu: the full daily history as CSV or JSON, and a one-page health report as PDF or straight to the printer. The report carries the device's identity, its latest figures, the daily health chart, the service forecast, and the monthly rollup.

Export is deliberately not Backup. Export is a plain table for humans and spreadsheets; Backup remains the versioned file that restore understands.

## The health report is more honest at the edges

A wear trend whose service date fell beyond the ten-year forecast horizon was being described as "health is holding", which is not the same thing. The report now distinguishes a genuinely flat trend from a decline that simply outruns the forecast, and says which one it found.

The report's monthly table is capped at 24 rows with a note, because printing scales the whole page to the sheet and an unbounded table from a years-old device shrank everything to unreadable. The CSV still carries the full history. Report dates are stamped in UTC, so a report reads the same wherever it is opened.

## Health tab layout

Device cards now sit on their own card background instead of running together across a hairline, and the daily table under the chart is capped at ten readings. The full run lives in the export.

## More careful when a device answers slowly

A question that timed out no longer has its follow-up asked over the same connection, where a late answer to the first question could have been mistaken for the answer to the second. And a junk answer over the cable no longer stops the Wi-Fi connection being tried, so a half-seated cable cannot hide a reading that would have worked.

## Returning to the tab no longer queues a second read

Leaving the iPhone and iPad tab and coming straight back could start a new read while the previous one was still finishing, with the two queueing behind each other. The returning tab now picks up the read already in flight instead.

Read-only as always: WhatBattery never changes how your devices charge.
