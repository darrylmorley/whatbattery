# WhatBattery 1.4.1

Fixes the in-app updater, which has been refusing its own download. macOS 14 and later, Apple Silicon.

## Read this first if you are on 1.4.0

The updater in 1.4.0 cannot install this fix. That is the bug itself: it rejects the download before anything gets installed, so it cannot fetch the version that repairs it.

Two ways to get this release:

- Click **View release** on the update banner, download the zip, and drag WhatBattery into Applications over the old copy.
- Or, if you installed with Homebrew, run `brew upgrade --cask whatbattery`. Homebrew does its own download and was never affected.

Once you are on 1.4.1 the updater works normally again.

## What went wrong

WhatBattery checks that an update is still coming from a GitHub host after following redirects, so a download cannot be quietly served from somewhere else. The list of accepted hosts was written into the app, and GitHub moved release downloads to a new one. The list expected `releases.githubusercontent.com`. The real host is now `release-assets.githubusercontent.com`.

The check did exactly what it was built to do. It was comparing against a stale list, so it turned down GitHub's own server and the update stopped with "Download redirected to an untrusted host".

Nothing was ever at risk from this. The download was refused, not accepted. The signature and notarisation checks that decide whether an update is real sit behind that step and never ran.

## Fixed

- The updater accepts GitHub's current release asset host, and still accepts the previous ones so older releases keep working.
- That host list now lives in the tested part of the codebase, with a test that fails if it goes stale again. It had been sitting in the one part of the app with no tests at all, which is why a stale entry could sit there unnoticed.

Read-only as always: WhatBattery never changes how your devices charge.
